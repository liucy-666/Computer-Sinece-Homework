## 2. 目标1~7分别是怎么做的

在具体实现时，目标1~7虽然方案不同，但整体测试流程是一致的：

1. 先按目标要求实现对应的预测结构和更新逻辑。
2. 再对 `traces` 目录下全部 13 个 BT9 trace 逐个运行。
3. 记录每个 trace 的 `MISPRED_PER_1K_INST`。
4. 最后按总指令数加权，得到整体 MPKI，用来比较不同方案。

下面把 1~7 的实现流程分别展开说明。

### 2.1 目标1：实现 1 位分支预测器，并测试

目标1做的是最基础的 1-bit 预测器，思路比较直接：

1. 先建立一个 1024 项的预测表。
2. 用 `PC >> 2` 作为索引，直接定位到表项。
3. 每个表项只保存 1 位信息，表示“上一次这个位置是跳转还是不跳转”。
4. 预测时，表项是 1 就预测 Taken，是 0 就预测 Not Taken。
5. 分支真正执行完以后，直接用真实结果覆盖原来的 1 位状态。

这个目标的重点不是追求最好效果，而是先建立最基本的“按历史一次结果做下一次判断”的分支预测流程。  
完成实现后，再把 13 个 trace 全部跑完，得到目标1的整体结果。

### 2.2 目标2：扩展全局分支历史长度，并测试

目标2在目标1的基础上，引入了全局历史信息，使用的是 `gshare` 思路：

1. 先维护一个全局历史寄存器，记录最近若干次分支的跳转结果。
2. 预测表中的每一项不再是 1 位，而是改成 2-bit 饱和计数器。
3. 预测时，把 `PC >> 2` 和全局历史做异或混合，得到预测表索引。
4. 读取对应的 2-bit 计数器，计数器偏向 Taken 就预测跳转，否则预测不跳转。
5. 分支执行完成后，先更新这个 2-bit 计数器，再把真实结果移入全局历史寄存器。

这一目标的核心不是只实现一个固定版本，而是扫描不同的历史长度。  
所以我分别测试了 `h=2`、`h=4`、`h=8`、`h=10`、`h=12`，然后比较它们的加权 MPKI，最后选出最优的一组作为目标2正式结果。  
从最终数据看，`h=12` 的效果最好。

### 2.3 目标3：为每个分支指令分配完全独立的状态机，并测试

目标3开始强调“每个静态分支自己维护状态”，而不是和别的分支共享同一个表项：

1. 先为静态分支建立独立表项，表项里保存该分支自己的 2-bit 饱和计数器。
2. 访问时根据分支 PC 查找对应项，如果这个分支第一次出现，就先分配并初始化状态。
3. 预测时直接读取这个分支自己的 2-bit 状态机。
4. 执行后只更新它自己的状态，不影响其他分支。

这样做的目的，是减少不同分支之间因为共享同一表项而产生的互相干扰。  
实现完成后，同样对全部 trace 逐个运行，再汇总目标3结果。

### 2.4 目标4：扩展为 3 位状态机，并测试

目标4沿用了目标3“每个静态分支独立维护状态”的结构，只把状态机从 2-bit 扩展成了 3-bit：

1. 保留“每个分支一个独立表项”的组织方式不变。
2. 把原来的 2-bit 饱和计数器改成 3-bit 饱和计数器。
3. 预测时，按照 3-bit 计数器当前所处区间判断 Taken 或 Not Taken。
4. 更新时，遇到 Taken 就向强 Taken 方向增加，遇到 Not Taken 就向强 Not Taken 方向减少。

这一目标主要是观察：状态机位数增加以后，能不能减少偶发翻转对预测结果的影响。  
测试流程仍然与前面一致，最后与目标3做直接对比。

### 2.5 目标5：实现局部历史信息，并测试

目标5开始引入局部历史，也就是“每个分支自己最近几次是什么模式”：

1. 先用 PC 的低位建立局部历史表，每个位置保存该类分支最近几次的局部历史。
2. 再建立模式历史表（PHT），表项使用 2-bit 饱和计数器。
3. 预测时，先根据分支 PC 找到它对应的局部历史。
4. 再把 PC 和这个局部历史组合起来，作为 PHT 的索引。
5. 读取 PHT 对应计数器，给出预测结果。
6. 分支执行后，同时更新两部分：一是更新 PHT 计数器，二是把真实结果移入该分支的局部历史寄存器。

这一目标的作用，是让预测器能学到“某个分支自己内部”的重复模式，而不只是看全局最近发生了什么。

### 2.6 目标6：实现局部 + 全局历史信息，并测试

目标6把目标2和目标5的思路合并起来，做成一个组合式预测器：

1. 一路用局部历史预测器，给出一个局部预测结果。
2. 另一路用全局历史预测器，给出一个全局预测结果。
3. 再额外维护一个 chooser（选择器），判断当前更应该相信哪一路。
4. 预测时，如果 chooser 更偏向局部，就采用局部结果；如果更偏向全局，就采用全局结果。
5. 更新时，局部和全局两边各自更新自己的计数器与历史信息。
6. 如果这两路结果不一致，就根据这次谁预测对了来更新 chooser。

这个目标的重点是利用两类信息的互补性：  
有些分支更像“自己内部有规律”，有些分支更像“会受前面其他分支影响”，所以组合后通常比单独一种方法更稳。

### 2.7 目标7：改用其他 hash 函数实现，并测试

目标7并没有推翻目标6的整体结构，而是在目标6基础上继续优化索引方式：

1. 保留“局部历史 + 全局历史 + chooser”的整体框架不变。
2. 原来目标6里很多索引位置是通过 XOR 混合得到的。
3. 在目标7里，把这些 XOR 混合改成了“移位 + 加法”的 hash 方式。
4. 目的不是改变预测逻辑本身，而是尽量减少不同分支在索引上的冲突。
5. 修改完成后，再用与目标6完全相同的 trace 集重新测试。

这一目标更像是“在结构不变的情况下做细节优化”。
从最终结果看，它确实比目标6又略好一点，说明索引冲突的减少是有收益的，只是收益没有结构升级那么大。

## 3. 最终版是怎么做的

可以把当前最终版 `predictor.c` 理解成“几层一起判断”的结构，不是只靠一个表来预测。

它主要有 4 部分：

1. 基础预测器
   - 这一层先给一个初步判断。
   - 它会同时参考 `bimodal`、局部历史和全局历史。
2. TAGE 主预测器
   - 这是最主要的一层。
   - 它会看不同长度的历史记录，尽量找到和当前分支最像的情况，再给出主判断。
3. Loop Predictor
   - 这层专门处理“很像循环”的分支。
   - 比如某个分支前面很多次都一样，到某一次突然翻转，这种模式它比较适合处理。
4. Statistical Corrector
   - 这一层可以理解成“最后再检查一遍”。
   - 如果它发现当前结果很可能有问题，而且把握比较大，就会把原来的预测改掉。

整个预测过程可以简单理解成：

1. 先给一个基础判断。
2. 再用 TAGE 做主要预测。
3. 如果发现是稳定循环模式，就让 loop predictor 帮忙。
4. 最后再让 statistical corrector 做一次保守修正。

分支真正执行以后，还会把这些表和历史信息一起更新，这样后面的预测会慢慢变准。

## 4. 这次做了哪些改进

如果用比较容易理解的话来说，这次改进主要有 3 点：

### 3.1 不再只靠一种预测方法

前面的基础实验，大多是在比较某一种方法单独用时的效果。
当前最终版不是只用一种方法，而是把几种不同的信息放在一起判断：

- 分支本身平时更容易跳还是不跳
- 这个分支最近几次是什么情况
- 前面别的分支会不会影响它
- 它有没有很明显的循环规律

这样做的好处是：不同类型的分支，可以尽量交给更合适的部分去处理。

### 3.2 让主预测部分更强

最终版里最核心的部分还是 TAGE。
它的思路不是只看一种固定长度的历史，而是同时看短一些的历史和长一些的历史。
这样一来：
- 短历史适合处理比较近的规律
- 长历史适合处理隔得更远的关联

所以它比只看单一历史长度的预测器更灵活。

### 3.3 再加一层补救

就算主预测器已经很强了，还是会有一些分支不太好预测。
所以最终版又加了两种“补救”方法：

1. `loop predictor`
   - 负责处理循环型分支。
2. `statistical corrector`
   - 负责在最后再修一遍明显不对的结果。

这两层不会一直强行接管，而是在它们自己“比较有把握”的时候才出手，所以不会把原来已经对的结果破坏太多。

最终代码结构（这部分手写好些）(GetPrediction函数)
1.Base Predictor
底层用的锦标赛预测器（Tournament Predictor）它并行运行基于指令地址的双模态预测（Bimodal）和基于局部/全局历史的饱和计数器（Saturating Counter），并通过一个动态选择器（Chooser）实时评估哪种模式的置信度更高，从而提供基础预测兜底。简单而言就是基于过去的状态
预测下一次的分支状态

2.TAGE（几何长度标签预测器）
最终代码还是Tagged Geometric History Length 预测器作为核心。它由多个预测表组成，这些表所参考的全局历史长度呈几何级数递增。预测时，系统会利用折叠历史进行哈希查表，采用部分标记匹配机制，寻找具有最长匹配历史的表项作为主提供者（Provider），从而精准捕获极长距离的相关性分支模式。

3.Loop Predictor（循环预测器）
由于传统的马尔可夫链预测器很难处理迭代次数过长的循环（大数组遍历这些）。该组件通过追踪特定分支的目标迭代数和当前迭代状态，一旦识别出高置信度的固定循环模式，会在循环跳出的瞬间，强制反转TAGE 的常规预测。

4.SC（统计相关器）
“最后的纠错层是一个统计相关器，本质上是一个轻量级的神经网络（感知机 Perceptron 模型）。它将多种特征哈希后映射到权重表中，将提取的权重进行代数累加得出 sc_sum。如果绝对值超过了动态调整的阈值，SC 会介入推翻 TAGE 的预测，极大提升了应对不规则分支的鲁棒性。

5.协作运行：

(1) 动态分配
拿AI的话来说就是：如果整个中心猜错了，系统不会干瞪眼。它会立刻火线招收一名新侦探，发给他更厚的档案本，让他专门记住这次翻车的教训。吃一堑长一智，下次再遇到就绝对不会错。就是当发生预测错误时，系统会在比当前匹配历史更长的高阶表中，寻找到有用位（Usefulness bit, 即 u 位）为空闲状态的表项，写入新的 Tag 和翻转后的预测状态。这使得模型能够自主学习并覆盖更复杂的未知分支模式。有点像神经网络里的backbone
(2)老化机制

为了防止有限的硬件存储被过时的数据塞满，系统引入了周期性有用位衰减机制。每经过一百万次分支（U_RESET_PERIOD控制），全局的有用状态位都会被右移衰减。状态淘汰与替换策略，有效避免了缓存污染，保证了预测器对程序执行阶段切换的快速适应能力。
